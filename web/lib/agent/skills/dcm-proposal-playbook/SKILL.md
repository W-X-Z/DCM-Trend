# 공모 회사채 제안서 암묵지 (Skill)

팀이 함께 쓰는 제안서 노하우다. 개인 선호는 여기 두지 않고 기억(Memory)에 둔다.

## 언제 무엇을 읽나

| 상황 | 읽을 파일 |
|---|---|
| 목차·장표 켜고 끄기, 템플릿 고르기 | `references/toc.md` |
| 발행 시기·증액 한도·밴드·비교 사례를 정하거나 설명할 때 | `references/rules.md` |
| 장표 문안을 쓰거나 고칠 때, 초안을 검토할 때 | `references/slide-tips.md`, `references/style.md` |

## 한 줄 원칙

- 근거 숫자 → NH 판단 순서로 쓴다. 숫자는 데이터(엔진 `dcm_facts`·`dcm_state`)에 있는 값만.
- 금리·수요의 방향을 예측하거나 단정하지 않는다. 출처 있는 의견만 "~에 따르면"으로.
- 발행금액·트랜치·금리는 발행사가 최종 결정한다. 제안은 근거와 함께 선택지로.
- 내부 데이터(민평 4사, NH 리서치 전망표·Discussion Material, 기관별 수요예측 북, FnGuide, 본드웹)는 아직 연계되지 않았다. 없는 값을 채우지 않는다.

## 규칙과 노하우의 차이

- `rules.md` 의 규칙은 엔진(dcm-deck-engine) 코드에 이미 들어 있다. 설명·근거로 쓰고, 값은 엔진이 계산한 것을 쓴다.
- `slide-tips.md` 의 노하우는 사람이 화면(`/proposal/knowledge`)에서 더하고 고친다. 엔진(`dcm_load`)이 받는 노하우가 최신이고, 이 파일은 2026-11-02 스냅샷이다. 둘이 다르면 엔진 쪽을 따른다.
- 노하우의 적용 등급이 정해져 있으면(예: A) 그 등급 회사에만 쓴다.
