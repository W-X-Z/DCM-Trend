# 딜 발굴 데스크 (에이전트 부서)

RM 이 영업하러 가기 전에 필요한 앞단을 부서가 알아서 돈다: 공시·뉴스로 시장을 보고, 돈이 필요해 보이는 회사를 고르고, 그 회사의 이슈와 과거 데이터를 조사해 미팅용 1pager 를 낸다.
RM 은 채팅으로 시키지 않는다. 아침에 "오늘 연락할 회사"와 1pager 를 받는다. 회사를 지정해 1pager 만 받을 수도 있다.

사외 프로토타입이다. 공개 자료(OpenDART, ECOS, 뉴스 검색 API, 웹 검색)만 쓴다. 콜리포트, 수요예측 실명, 고객 커버리지 리스트 같은 내부 자료는 넣지 않는다.

## 흐름

| 순서 | 부서 | 누가 | 하는 일 | 남기는 것 |
|---|---|---|---|---|
| 0 | 수집실 | 코드 | 공시·금리는 기존 수집기(`ingest/`), 뉴스는 `desk/news.py`(네이버 뉴스 검색 API, 검색어는 `ref.desk_news_queries` 행) | `raw.filings`, `raw.news` |
| 1 | 모니터링팀 | Haiku ×3 | 아직 안 읽은 주요 공시(4묶음)와 기사에서 자금 수요 신호만 남김. 상장폐지·횡령·해산은 '영업 주의'로 표시 | `desk.signals`, `desk.seen` |
| 2 | 발굴팀 | Sonnet | 회사별 신호(최근 14일)와 규칙 후보(공모채 만기 3~6개월 전, 메자닌 풋, 단기 차입 의존)에서 대상을 최대 3곳 고르고 가설·질문·제외 조건을 씀 | `desk.leads` (대기) |
| 3 | 조사팀 | Sonnet ×3 + 웹 검색 | 확인 넷(수요, 여력, 시기, 아직 열려 있는가)과 사업·이슈·유사 사례. 제외 조건에 걸리면 기각 | `leads.research` |
| 4 | 브리핑팀 | Sonnet ×3 | 1pager 의 글 칸. 표는 코드가 데이터로 그림 | `leads.brief`, `brief_md` |
| 5 | 검수팀 | Sonnet ×3 + 웹 검색 | 작성 과정을 모른 채 1pager 를 공시 DB·공시 목록·보도와 대조. 유지·수정·보류 | `leads.verify`, 상태 게시·보류 |

- 가설을 보드에 먼저 적고 나서 조사한다. 검수를 거치지 않은 1pager 는 게시되지 않는다.
- 단계마다 결과를 보드에 붙여 둔다. 비용 상한이나 오류로 멈추면 다음 실행이 끝난 단계를 건너뛰고 이어 한다.
- 본 공시·기사는 다시 읽지 않고, 보드에 오른 회사는 14일 동안 다시 고르지 않는다.
- 에이전트 정의(지침, 출력 형식, 모델, 인원)는 `desk/agents.py` 한 곳에 있다. 호출마다 `desk.calls` 에 한 줄(일감, 요약, 토큰, 검색 수, 비용)이 남는다.

## 1pager 구성

왜 지금(자금 수요와 근거 신호) / 회사(처음 보는 산업도 알 수 있게) / 최근 실적(분기 표) / 차입과 만기(현금·차입·부채비율, 1년 내 만기, 만기·풋 표) / 조달 이력(조건, 주관사) / 최근 이슈 / 유사 사례(같은 등급군 공모채 또는 같은 시장 메자닌·유상증자) / 미팅 토킹포인트 / 검토할 수 있는 방향 / 확인하지 못한 것 / 검수 / 출처.

표의 숫자는 DB 와 OpenDART 재무제표에서 코드가 넣는다. 구성은 SME RM(11/12), 인더스트리 RM(11/13), 시니어 RM(11/19) 인터뷰에서 나온 항목이다.

## 실행

```bash
python3 -m desk daily [--days 3] [--force]     # 하루 실행
python3 -m desk resume                         # 새 대상 없이, 끝내지 못한 대상만 이어서
python3 -m desk brief 롯데관광개발              # 회사를 지정해 1pager 만
python3 -m desk news                           # 뉴스 수집만
python3 -m desk fin 00231372                   # 재무 도구 결과 확인
python3 -m desk config                         # 사무실 화면 설정(JSON)
npm run test:desk                              # SQL 함수 시험 (PGlite)
npm run test:desk-run                          # 실행 코드 시험 (가짜 Supabase·Claude·OpenDART 로 전 구간)
```

GitHub Actions `desk-daily` 는 수동 실행만 둔다. 결과는 실행 요약과 첨부(`desk-out`), DB 의 `mart.v_desk_briefs`·`v_desk_board`·`v_desk_signals`·`v_desk_runs`·`v_desk_calls` 에 남는다.

## 화면

AX 플랫폼 Agent 갤러리의 'RM 미팅 준비' 카드에서 본다. 사무실 화면은 `mart.v_desk_runs`·`v_desk_calls` 를, 결과물 화면은 `v_desk_board`·`v_desk_briefs` 를 읽는다.
부서·에이전트 구성이 바뀌면 `python3 -m desk config` 결과를 AX 플랫폼의 `src/desk/config.json` 에 다시 넣는다.

## 켜는 순서

1. 이 변경을 병합한다.
2. 운영 DB 에 `supabase/migrations/20261122140000_desk.sql` 을 적용한다.
3. 저장소 시크릿에 `ANTHROPIC_API_KEY` 를 넣는다. 뉴스를 쓰려면 네이버 뉴스 검색 API 키 한 쌍도 넣는다: `NAVER_HUB_CLIENT_ID`·`NAVER_HUB_CLIENT_SECRET`(네이버 클라우드 NAVER API HUB) 또는 `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET`(네이버 개발자센터). 없으면 공시만으로 돈다.
4. `desk-daily` 를 수동으로 한 번 돌려 결과와 비용을 본다. 그 뒤 워크플로의 예약 주석을 푼다.

## 비용

실행 상한 `DESK_USD_CAP`(기본 5달러). 상한은 새 호출을 막는 방식이라 이미 시작한 호출만큼 넘을 수 있다. 조사는 뒤 단계 몫 0.5달러를 남기고 시작한다.
첫 실행(2026-11-22, 공시 29건·대상 3곳, 3분 40초)은 1.63달러였다: 모니터링 0.002, 발굴 0.05, 조사 건당 0.28~0.37(검색 5~7회), 브리핑 건당 0.04, 검수 건당 0.26~0.28. 대상 한 곳을 끝까지 하면 약 0.6달러다.
모델은 환경변수로 바꾼다: `DESK_MODEL_MONITOR`, `DESK_MODEL_SCOUT`, `DESK_MODEL_RESEARCH`, `DESK_MODEL_BRIEF`, `DESK_MODEL_VERIFY`. 하루 대상 수는 `DESK_MAX_LEADS`.

## 확인되지 않은 것과 한계

- Claude API 와 OpenDART 재무 API 는 첫 실행(2026-11-22)에서 돌았다. 네이버 검색 API 는 키가 없어 아직 돌리지 않았다.
- 첫 실행에서 고친 것: 조사 담당이 '제외 조건 해당 없음'을 글로 적은 것을 해당으로 읽어 기각함(→ kill.hit 참·거짓으로), 검수 결과의 형식이 어긋나 결과를 잃음(→ 형식 보정, 호출 출력 기록), 검수가 글 칸에 표를 다시 그림, 유사 사례에 금융채·신종자본증권이 섞임(→ `desk_comps` 를 같은 종류로).
- 재무: 12월 결산 기준으로 보고서를 찾는다. 차입 합계는 계정 이름으로 더한 값이라 회사마다 겹치거나 빠질 수 있다. 4분기는 연간에서 3분기 누적을 뺀다.
- 뉴스: 검색어에 걸린 기사의 제목·요약 한 줄만 본다. 회사 이름이 DB 의 회사명과 정확히 같을 때만 회사 코드가 붙는다.
- 주가·시가총액, 신용등급 변경, 사모사채 발행은 수집하지 않는다.
- RM 의 피드백(연락함·보류·제외)과 읽는 화면은 아직 없다.
