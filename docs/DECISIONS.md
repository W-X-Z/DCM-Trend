| 제안서 초안 화면 단순화 (10-29) | 제안서 작성은 **새 탭**(사이트 머리글·바닥글 없는 작업 화면)으로 연다. 탭은 **미리보기 · 데이터 · 흐름도** 셋, 오른쪽 위 **다운로드**(PPT·PDF 드롭다운), 오른쪽에 **Agent 채팅**(추천 요청 칩 3개, 접으면 얇은 띠만 남고 이 브라우저에 기억). 미리보기에 **전체보기**(화면 가득, ←·→·Esc). 데이터는 외부·내부 표 두 개, 각 6건 + 펼치기(기관 구분은 출처 칸으로), 내부 데이터는 목록과 '미연계' 표시만. 흐름도는 구성도(p2) 깊이로: 초안 작성·채팅 → Agent(의도 해석 LLM → 실행 계획 코드) → 초안(미리보기 → 확인 → PPT·PDF, 다음 요청으로 돌아감), Agent 아래 암묵지(Skill: 템플릿·목차·장표별 팁·작성 규칙)·도구(Tool: 계산·조회·문안·산출·검수)·기억(Memory: 덱 상태·대화), 도구 아래 데이터 수집 → 외부·내부 데이터. 상자를 누르면 짧은 항목으로 열린다. 목차 칩·검토 표시 토글·발행 조건·일정·사례·문안·내부 데이터·표지 탭과 Sales AI 버튼은 화면에서 뺐다. 조건·목차·문안은 채팅으로 바꾼다: LLM(`/api/deck/agent`)은 요청을 정해진 행동 목록(트랜치·증액 한도·납입일·수요예측일·밴드·이자지급·등급·수수료·회차·장표 켜고 끄기·템플릿·사례 범위·Sales AI·문안 고치기·이동·되돌리기)으로 해석만 하고, 값 검사와 반영은 코드(`web/lib/deck/agent.ts`)가 한다. 트랜치 금액이 바뀌면 증액 한도는 같은 규칙으로 다시 계산. 문안 고치기는 사실 묶음에 없는 숫자·전망 표현이 든 줄을 버린다. 첫 인사는 '○○ 제N회 공모사채 제안서 초안 N장을 만들었어요. 딜 조건이나 전략을 바꾸고 싶으시면 편하게 말씀해주세요.' 확인할 곳 수는 흐름도(초안·검수)에 둔다. 데이터 탭은 수집한 외부 데이터(출처·기준일·쓰인 장표)와 회사 내부 데이터(값 칸 비움)를 나열 | 포털 구성도의 '의도 해석(LLM) → 실행 계획(코드)'을 그대로 구현. 채팅 대화는 저장하지 않음 |

## 데이터 범위의 알려진 한계 (10-15 점검)

| 항목 | 내용 |

| 일괄신고 채무증권 | 은행·카드·캐피탈·금융지주·발전 자회사가 쓰는 `일괄신고추가서류` 는 수집하지 않는다. 금감원 '일반회사채' 집계(26.07 2.78조)보다 우리 일반회사채 합계(같은 달 1.13조)가 작은 주된 이유. 금융채·공기업 만기도 일부만 보인다 |
